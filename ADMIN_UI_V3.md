# Оновлення лише адмінки, v3

Архів оновлення призначений для останнього наданого проєкту `mykep-dev.zip (2).txt`. Це не самостійний проєкт. У ньому є лише змінені файли `admin_static/`, новий браузерний тест та ці нотатки. Скопіюйте файли поверх відповідних файлів у наявному проєкті. Не видаляйте папки перед копіюванням.

## Що змінилося

Нейтральна темна палітра з помаранчевим акцентом MyKep, пласкі поверхні без декоративних градієнтів, світіння й анімованих фонів. Менші заокруглення, прямокутні елементи керування, показники в єдиній сітці з роздільниками замість набору великих карток. Тексти уточнено, декоративні емодзі прибрано. Статуси мають текстові підписи, а не лише колір.

Ширина `.app`, `.content`, `main`, `.page`, внутрішніх сіток і графіків явно обмежена батьківським контейнером. У `.page` замість неявної auto-колонки використано `minmax(0, 1fr)`. Для графіків додано inline-size containment. Прибрано маскування переповнення через `overflow-x: hidden/clip` на сторінці та картках. SVG використовують фактичну ширину контейнера, а не мінімум 280/300 px. Підписи крайніх точок та підказки утримуються в межах графіка.

На телефоні графіки розташовано в одну колонку. Показники на найвужчих екранах теж переходять в одну колонку; подвійний показник повернень займає повний рядок. Періоди розміщено у два ряди, кнопки експорту не виходять за екран. У компактній таблиці груп прибрано лише декоративні смуги, числові дані збережено. Довгі назви, IP-адреси та значення переносяться. Враховано safe-area з усіх боків і нижню навігацію PWA.

Лінійні, стовпчикові графіки та теплова карта мають блок «Показати значення». Це справжні HTML-таблиці, доступні з клавіатури й на сенсорному екрані. Кнопки мають мінімальну висоту 44 px. Поля введення мають шрифт 16 px, щоб не викликати автоматичне збільшення в Safari. Збережено видимий фокус і reduced-motion.

Періоди використовують звичайні кнопки з `aria-pressed`, а не неповний ARIA tablist. Експорт теж використовує кнопки, доступні з клавіатури. Застаріла відповідь API після швидкого перемикання періодів не замінює актуальні дані. Автооновлення призупиняється, коли фокус у контенті або відкрита таблиця графіка. Старі ResizeObserver від’єднуються при перемальовуванні. Додано обмеження очікування GET-відповіді; автоматичних повторів операцій запису немає.

Версії ресурсів і кеш адмінки змінено на v3. Основний service worker не змінювався. API, статистика й сесії не додаються до кешу адмінки.

## Фактично виконані перевірки

Bun успішно розібрав три JS-файли та CSS. Oxlint: 0 помилок, 0 попереджень. Новий Python-тест компілюється.

У полегшеній моделі DOM із синтетичними даними пройшли побудова всіх чотирьох екранів, перемикання періодів і показників, передавання CSRF-заголовка, створення тестового коду входу, текстовий вивід XSS-рядка. Перевірено, що повільна відповідь попереднього періоду не перемагає нову, а помилка мережі зберігає останні дані та показує повідомлення.

Розрахункова ширина SVG перевірена на 120, 220, 254, 288, 326, 600 і 1000 px. Перевірені таблиці значень, включно з усіма комірками тестової теплової карти. Це перевірка JS-геометрії, не браузерної верстки.

Контраст основного, другорядного й допоміжного тексту на фоні картки: 15.22:1, 9.32:1 і 7.63:1. Текст основної кнопки: 6.74:1; Telegram-кнопки: 6.84:1. Це окремі вимірювання палітри, не сертифікація WCAG.

## Що ще треба перевірити локально

У середовищі виконання немає браузера, Playwright або FastAPI. Браузерний тест, реальний HTTP-сервер, візуальна перевірка та Safari/PWA не запускалися. Скріншоти нової версії не створювалися. Не вважайте відсутність переповнення на реальному iPhone підтвердженою до перевірки нижче.

Запускайте локальний сервер на окремій демо-базі, не на `schedule.db`. Для dev-входу потрібні процесні змінні `MYKEP_DB_PATH`, `ADMIN_DEV_LOGIN=1`, `ADMIN_COOKIE_SECURE=0`, `BOT_MODE=disabled`. Не зберігайте їх у production `.env`. Перевірте чинні `ADMIN.md` і `.env.example`: origin повинен відповідати localhost, а не production-домену.

Якщо Playwright уже є в локальному середовищі, запустіть:

````sh
python scripts/admin_ui_regression.py --browser both
````

Якщо його немає, встановіть локально як інструмент тестування, не додаючи до production requirements:

````sh
python -m pip install playwright
python -m playwright install chromium webkit
python scripts/admin_ui_regression.py --browser both
````

Скрипт допускає лише локальний HTTP-сервер, відкриває адмінку через dev-вхід і не оновлює розклад, не відкликає сесії, не виконує експорт. Він перевіряє 320, 360, 375, 390, 414, 768, 1024 і 1440 px; усі розділи; кілька періодів; таблиці; підказки; клавіатурний фокус. Перевіряється геометрія самих карток, а не лише ширина документа. При помилці скрипт завершується ненульовим кодом. JSON-звіти й скріншоти записуються в ігнорований `test-results/admin-v3/`.

Автотест навмисно блокує service worker для відтворюваної перевірки свіжої верстки. Оновлення встановленої PWA перевірте окремо, не очищуючи дані основного сайту: відкрийте адмінку онлайн, дочекайтеся активації `mykep-admin-v3`, закрийте й відкрийте її знову. Вручну перевірте Safari та PWA на iPhone, портретну й альбомну орієнтацію, прокрутку всіх розділів, збільшений текст і показ/приховування клавіатури. Емуляція WebKit не дорівнює реальному iPhone.

## Відкат

Поверніть попередні шість файлів адмінки зі своєї резервної копії, але використайте новий ідентифікатор кешу, наприклад `mykep-admin-v3-rollback`, і нові query-версії ресурсів. Дані та міграції для цього оновлення не потрібні. Не відновлюйте й не видаляйте production-базу для відкату дизайну.

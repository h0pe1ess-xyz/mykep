# MyKep 2.6.2 — лише геометрія навбара iOS PWA

Користувач підтвердив: проблема залишається у встановленому PWA на iPhone з версією 2.6.1. Інший інтерфейс схвалено; Android не перевірено. Це окрема спроба виправлення, не підтверджений реліз для iPhone.

## Зміна

Попередній responsive.css задає body та app-container висоту 100dvh. Старий варіант до оновлення використовував 100vh. Додано js/display-mode.js у head усіх трьох сторінок: клас ios-standalone встановлюється лише для iOS + navigator.standalone або display-mode: standalone (включно з iPad desktop UA).

Новий css/ios-standalone.css завантажується після responsive.css і тільки для цього класу повертає повну висоту: 100vh, потім явний сучасний еквівалент 100lvh. Навбар позиціонується absolute, bottom:0 у цьому контейнері. Він більше не залежить від висоти flex-рядка чи окремої системи координат position:fixed. Не використовуються screen.height, від’ємний bottom або вгадані висоти панелей Safari.

Safe area не вимикається. Фон навбара доходить до нижнього краю; кнопки мають 10px + нижній safe-area відступ. Місце для прокручуваного вмісту резервується окремо: 48px кнопки + 20px звичайні відступи + нижня safe area. Верхній відступ під статусбар і viewport-fit=cover збережено.

Safari у вкладці, Android та desktop не отримують нових правил. Код вибору групи, PWA-підказок, основні layout.css і responsive.css, усі Python-файли побайтово ідентичні 2.6.1. Статичні URL і Service Worker оновлено до 2.6.2.

## Перевірено

У the Computer пройшли 37 Node-тестів (29 попередніх + 8 нових). Нові тести перевіряють увімкнення класу тільки для iOS standalone, відсутність його для Android/Safari/desktop, порядок CSS та структуру прив’язки навбара. node --check пройшов для всіх JS. HTML head-скрипти й унікальність ID перевірено.

Це тести JavaScript і вихідного CSS з мінімальною моделлю DOM, НЕ рендеринг у WebKit. Реальний iPhone, Safari, Android та VPS не запускалися. Вплив 100dvh на проблему — робоча гіпотеза, а не доведена причина. Старі QA-файли в архіві — історія попередніх версій.

## Приймання

Запустити оновлений сайт у локальному тестовому середовищі та встановити/відкрити PWA саме цього origin через довірений HTTPS. Не вважати PWA production-домену автоматично пов’язаним із localhost. На iPhone перевірити версію 2.6.2, закрити й відкрити PWA після оновлення Service Worker. Не видаляти PWA чи збережену групу без дозволу.

Перевірити всі три вкладки в portrait та landscape, повернення з фону, прокручування налаштувань до останнього блока, модальне вікно групи з клавіатурою. Навбар має залишатися біля нижнього краю, фон — до краю екрана, кнопки — вище home indicator. Safari та Android мають зберегти вигляд 2.6.1.

Якщо проблема лишилась, через Safari Web Inspector для САМЕ встановленого PWA виконати:

````js
JSON.stringify(window.mykepViewportReport(), null, 2)
````

Це локальна діагностика, вона нічого не надсилає. Повертає версію, режим, активність iOS-фікса, innerHeight/clientHeight/visualViewport, виміряні 100vh/100dvh/100lvh, safe-area відступи та прямокутники body/app/nav. Не читає групу, URL, сховище або секрети. Разом із результатом потрібен актуальний скриншот. Якщо функції немає або версія не 2.6.2 — завантажилася інша збірка.

Не застосовувати подальші випадкові зміщення bottom/padding: спочатку порівняти app.bottom, nav.bottom і виміряні viewport-висоти.

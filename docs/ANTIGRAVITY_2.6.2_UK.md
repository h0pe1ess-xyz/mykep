# Antigravity: MyKep 2.6.2, тільки навбар iOS PWA

Прикріплено повний mykep-updated-2.6.2.zip. База — попередній 2.6.1. Я підтвердив, що саме у встановленому iPhone PWA версії 2.6.1 навбар досі зависоко; решта інтерфейсу мене влаштовує. Не переробляй дизайн, вибір групи або екран встановлення.

## Інтеграція без втрати локальних змін

Розпакуй ZIP у тимчасову папку, знайди мій репозиторій https://github.com/h0pe1ess-xyz/mykep і перевір git status/diff. Зроби резервну копію локальних правок. Не використовуй reset --hard, git clean, force push чи автоматичне стирання файлів. Не чіпай .git, .env, .venv, бази, токени, логи й робочі кеші. Не виводь секрети.

Прочитай docs/NAVBAR_2.6.2_UK.md. Порівнюй лише зміни, перелічені в docs/changed-files-2.6.2.txt; baseline-хеші попереднього 2.6.1 є в docs/BASELINE_2.6.1_SHA256.json. Якщо локальні файли відрізняються від бази — збережи власні правки та об’єднай вручну; за суттєвого конфлікту запитай мене. Не копіюй весь старий серверний код поверх локальних виправлень.

Суть: нові js/display-mode.js та css/ios-standalone.css, їх підключення в HTML/style.css/Service Worker; нові тести; версія статичних ресурсів 2.6.2. Для встановленого iOS: 100vh/100lvh та absolute bottom:0 всередині повновисотного app-container. Safari й Android залишаються на верстці 2.6.1. Верхня safe area збережена, нижня є тільки в навбарі плюс відповідний резерв під ним у контенті. Не скидай safe area до нуля й не вимикай масштабування.

## Спочатку локальна перевірка, не Git

Запусти node --test tests/frontend.test.cjs (очікується 37 успішних тестів), node --check для JS. Запусти локальний вебсервер з ізольованими тестовими даними. Не запускай Telegram-бота з робочим токеном. Не підключайся до VPS/SSH і нічого там не змінюй.

Дай мені адресу для перевірки на iPhone. Для PWA на фізичному телефоні потрібен довірений HTTPS. Звичайний http://LAN-IP — не повноцінна перевірка встановленого PWA. Не публікуй сервер в інтернет або не створюй тунель без погодження. Переконайся, що PWA запускає саме оновлений тестовий origin, а не інший сайт. На телефоні має бути версія 2.6.2. Перевір Service Worker і URL ресурсів ?v=2.6.2; не очищай дані/не видаляй PWA без мого дозволу.

Перевір навбар у встановленому iPhone PWA: усі три вкладки, portrait/landscape, після згортання й повторного відкриття, прокручування останньої картки, клавіатура у виборі групи. Без великої порожньої смуги під навбаром, але кнопки не під системною смужкою. Перевір Safari/Android на регресії, якщо маєш пристрої. Chromium-емуляція не доводить правильність WebKit.

Якщо навбар досі не на місці, НЕ підбирай нові CSS-відступи навмання. Через Safari Web Inspector саме встановленого PWA виконай JSON.stringify(window.mykepViewportReport(), null, 2), збережи результат та скриншот. Якщо не маєш доступу до такого інспектора — поясни це й попроси мене надати дані. Ця функція нічого не надсилає, не читає сховище чи групу. Порівняй app.bottom/nav.bottom, висоти vh/dvh/lvh та safe-area. Виправлення в ZIP — гіпотеза, доки я не підтверджу результат на iPhone.

Зараз НЕ роби commit, push або merge. Покажи результати тестів, diff і локальну версію. Тільки після мого явного дозволу — commit/push погоджених файлів в окрему гілку, без архівів, секретів чи тестових даних, без force push і merge у main.

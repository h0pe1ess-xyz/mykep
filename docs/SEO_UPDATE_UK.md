# MyKep 2.6.6 - SEO-оновлення

## Що змінено

База: **mykep-main2_6_5.zip.txt**, внутрішня версія **2.6.5-mobile5**. SEO внесено безпосередньо у файли цього архіву, не накладанням старого знімка 2.6.4. Усі файли актуальної бази збережено.

Канонічний домен цього пакета - **https://mykep.pp.ua/**. MyKep описано як незалежний студентський PWA-застосунок для ВСП «Фаховий коледж електронних приладів ІФНТУНГ», а не офіційний сервіс коледжу. Статус незалежного проєкту підтверджено власником у розмові.

| Ділянка | Зміни |
|---|---|
| Головна | Інформативний title, description, canonical, українська мова, посилання з наявного заголовка на сторінку про проєкт; без додаткового блоку під таймером |
| Пошуковий опис | `data-nosnippet` на встановлювальному діалозі та онбордингу; Google усе одно сам обирає опис |
| Соціальні мережі | Open Graph і Twitter Card, абсолютні URL, власна картинка 1200×630 з наявною іконкою MyKep |
| Структуровані дані | JSON-LD WebSite, WebApplication, WebPage / AboutPage, стабільні ідентифікатори сутності; без вигаданих рейтингів, офіційного схвалення чи пошуку, якого немає |
| Публічна сторінка | `/about.html`, читається без JavaScript та без встановлення; функції, обмеження офлайн-режиму, першоджерело, статус |
| Файли роботів | `/robots.txt`, `/sitemap.xml`, `/llms.txt`, `/llms-full.txt` |
| Канонічна адреса | `/index.html` → `/` через 308 у FastAPI, параметри запуску збережено |
| Навігація | Справжні посилання замість JS-only кнопок; активна сторінка працює і для `/`, і для `/index.html` |
| PWA | Узгоджена версія ресурсів і кешу 2.6.6; сторінка «Про MyKep» доступна з нового офлайн-кешу |
| Тести | 43 наявні JavaScript-тести з 2.6.5, 12 статичних SEO-тестів, 7 нових HTTP-тестів та SEO/PWA unit-перевірки |

Інтерактивні `/schedule.html` і `/settings.html` мають `noindex, follow`: це залежні від вибору користувача екрани застосунку, а не самостійні статичні публікації. У sitemap - лише головна й `/about.html`. API та службова документація мають заголовок `X-Robots-Tag: noindex`. Текстові файли для роботів теж мають `noindex` у HTTP-заголовку, щоб не конкурувати з основними сторінками у результатах пошуку; їх завантаження не заблоковано. `robots.txt` дозволяє сканування, зокрема CSS та JavaScript.

`noindex` не є захистом приватних даних. Схему зберігання, аналітику, API розкладу й налаштування користувачів це оновлення не змінює. Manifest `id`, `start_url`, `scope` і ключі localStorage збережено. Автоматичне очищення Service Worker стосується старих кешів оболонки `mykep-cache-*`, як і раніше, а не localStorage.

## Що збережено з 2.6.5

Файли Android-компонування, mobile-fit, gesture-guard, розклад, таймер, довідник викладачів, нові іконки та всі попередні тести збережено. У teacher-hints.js змінено тільки версію URL кешованого JSON. Нову поведінку appinstalled і повідомлення про HTTP/HTTPS залишено; PWA-діалог лише отримав SEO-атрибут та посилання на опис. CSS safe-area, сітка, розміри таймера й алгоритм ущільнення карток не змінені.

У головний екран не додано нових карток чи рядків: існуючий заголовок «Розклад на сьогодні» став посиланням «Розклад КЕП ІФНТУНГ» на /about.html. Сторінка з детальним описом має окремі стилі й не підключає mobile-fit чи gesture-guard.

## Як безпечно накласти на наявний проєкт

ZIP містить повний оновлений знімок коду з папкою `mykep-main/`. **Не копіюйте весь знімок на новішу версію проєкту без порівняння.** `UPDATE_MANIFEST.json` містить лише нові/змінені файли, SHA-256 їхньої початкової версії з наданого ZIP та оновленої версії. Безпечний спосіб - розпакувати в тимчасову папку, звірити SHA-256 і переносити лише файли з маніфесту. Якщо початкові хеші не збігаються, потрібне ручне злиття, а не сліпе перезаписування.

Якщо поточний файл уже має `updated_sha256`, його можна пропустити. Якщо новий файл уже існує й має інший вміст, це теж конфлікт. Не видаляйте файли, яких немає в архіві. Не чіпайте `.git`, `.env`, середовища, бази SQLite, локальні секрети або зміни користувача. Збережіть резервну копію поза репозиторієм. Архів і резервні копії не повинні потрапити в git.

## Перевірки

Запуск з кореня проєкту на Python 3.11+:

```sh
python -m unittest discover -s tests -p 'test_seo_*.py' -v
node --test tests/*.test.cjs
node tests/test_seo_client.cjs
```

Ці вибіркові SEO-перевірки не запускають наявний Python-модуль тестів довідника викладачів, якому потрібен aiosqlite. Без залежностей FastAPI 7 HTTP-тестів буде пропущено з явним повідомленням. Це не означає, що HTTP-перевірка пройшла. Для повної перевірки у локальному віртуальному середовищі:

```sh
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
```

HTTP-тести використовують справжній FastAPI через ASGITransport, але навмисно не запускають lifespan: без бота, фонових звернень до коледжу й записів у БД. Окремо потрібен справжній локальний запуск і перевірка у браузері.

Для ручного локального запуску задайте **в середовищі процесу** `BOT_MODE=disabled` та `MYKEP_DB_PATH` як шлях до окремої тестової SQLite-бази поза репозиторієм, після чого запускайте:

```sh
python -m uvicorn main:app --host 127.0.0.1 --port 8000
```

Не змінюйте production `.env`. Якщо джерело розкладу недоступне і тестовий кеш порожній, `/api/health`, `/api/groups` та `/api/schedule` можуть повертати 503 - це наявна поведінка холодного запуску, а не автоматично SEO-регресія. Не підміняйте реальні дані й не запускайте Telegram-бота заради SEO-перевірки.

У браузері перевірте головну, розклад, налаштування, онбординг, вибір групи, таймер, установлення/продовження у браузері, посилання «Про MyKep», фокус клавіатури, мобільні ширини та відсутність перекриття нижньої навігації. Окремо - оновлення вже встановленої PWA з кешу 2.6.5-mobile5 до 2.6.6 зі збереженням групи та офлайн-режим після першого успішного завантаження. iOS standalone потребує перевірки на справжньому пристрої або відповідному симуляторі.

Локальні canonical/og:url навмисно вказують на production-домен. Не замінюйте їх на localhost перед комітом. Локальний сервер слухає лише 127.0.0.1; не публікуйте тестовий запуск через тунель.

## Результат перевірок під час підготовки пакета

- 12 статичних SEO Python-тестів пройдено.
- Усі 43 наявні JavaScript-тести з архіву 2.6.5 пройдено. У тесті кешу змінено лише очікувану версію на 2.6.6.
- Наявні 7 Python-тестів довідника викладачів не запускалися через відсутній aiosqlite; їхній код залишено без змін. Повний discovery потрібно виконати локально після встановлення requirements-dev.txt.
- 7 HTTP-тестів пропущено: у середовищі підготовки немає FastAPI/httpx/aiosqlite; встановлення пакетів недоступне.
- Синтаксис Python перевірено, `node --check` для всіх JS-файлів пройдено.
- JavaScript unit-перевірки пройдено: життєвий цикл SW, збереження сторонніх кешів, онлайн/офлайн fallback, виключення API, 404 та активна навігація. Використано тестові замінники браузерних API, а не справжній браузер.
- Візуальний тест, справжній запуск FastAPI, live-сайт, Google Search Console і production-конфігурацію проксі тут не перевірено. Пуш, деплой та інші зовнішні зміни не виконувались.

## Після підтвердженого пушу й деплою

Спочатку перевірте фактичні HTTPS-відповіді production: `/`, `/about.html`, `/robots.txt`, `/sitemap.xml`, `/llms.txt`, `/llms-full.txt`, картинка та `/sw.js` - 200 з правильними MIME-типами; `/index.html` - 308 на `/`; неіснуюча сторінка - 404. На `/` і `/about.html` не повинно бути `noindex` від CDN/проксі, блокування роботів чи сторінки challenge. Наявний приклад Nginx проксіює ці шляхи у FastAPI, але фактична конфігурація сервера невідома. Якщо Nginx віддає статику напряму, редирект і HTTP-заголовки з main.py потрібно окремо відтворити на цьому рівні.

У Google Search Console підтвердьте право власності на `mykep.pp.ua`, подайте `https://mykep.pp.ua/sitemap.xml`, перевірте головну та `/about.html` через URL Inspection і запросіть індексацію. Перевірте відрендерований HTML та обраний Google canonical. Для JSON-LD можна використати Schema Markup Validator і Google Rich Results Test; валідна схема не гарантує розширеного результату. Перевірте прев’ю посилання у Telegram/Viber: ці сервіси можуть певний час зберігати стару картинку й текст у кеші.

Найкорисніше зовнішнє доповнення для розрізнення однойменних проєктів - справжні посилання на `https://mykep.pp.ua/` з контекстом «MyKep - студентський розклад КЕП ІФНТУНГ»: сайт/новини коледжу за згодою адміністрації, студентські канали, README репозиторію. Звернення до коледжу чи публікація в каналах потребують окремого погодження; пакет цього не робить. Не купуйте посилання, не створюйте фальшиві відгуки й не дублюйте сотні сторінок із ключовими словами.

Пошукова видача залежить від запиту, місця, мови й інших сигналів. Краще відстежувати і «mykep», і «mykep кеп», «mykep розклад», «розклад кеп іфнтунг». Сам Google визначає title, snippet, показ AI-огляду та джерела в ньому. Повторне сканування й переоцінка не мають гарантованого строку.

**Перше місце та згадку саме вашого застосунку в Gemini/AI Overview гарантувати неможливо.** `llms.txt` і `llms-full.txt` - додаткові загальнодоступні описи; це не обов’язковий стандарт Google, не спеціальна команда для Gemini і не підтверджений фактор ранжування. Основна робота тут - коректні індексовані HTML-сторінки, послідовна ідентичність, технічна доступність і правдивий зміст.

# Завдання для Antigravity: MyKep 2.6.1

Прикріплений mykep-updated-2.6.1.zip — повний проєкт на базі ще не опублікованого 2.6.0. Я вже перевіряв 2.6.0 локально, тепер треба застосувати інтерфейсні виправлення й дати мені перевірити їх ще раз. Репозиторій: https://github.com/h0pe1ess-xyz/mykep.

## Спочатку тільки локально

Знайди мій робочий репозиторій, перевір git status, поточну гілку й diff. Розпакуй архів у тимчасову папку поза репозиторієм, прочитай docs/HOTFIX_2.6.1_UK.md. Не копіюй вкладену папку проєкту всередину проєкту.

Збережи резервну копію локальних змін. Не застосовуй reset --hard, git clean, автоматичний stash або примусове перезаписування. Не чіпай .git, .env, .venv, бази SQLite, логи, кеші та секрети. Архів їх не містить. Не виводь секрети в консоль або звіти.

У docs/changed-files-2.6.1.txt перелічено зміни відносно переданого раніше архіву 2.6.0, а docs/BASELINE_2.6.0_SHA256.json містить хеші відповідних файлів базової версії. Якщо локальний файл не збігається з базою, порівняй його зміни та об’єднай їх обережно. Не затирай власні локальні правки, не відновлюй старий код сервера поверх локальних виправлень. Якщо є суттєвий конфлікт — запитай мене.

Якщо в робочій папці ще немає 2.6.0, архів містить повну версію, але перед інтеграцією спочатку покажи мені масштаб різниці. Серверний Python-код у 2.6.1 не змінювався порівняно з 2.6.0.

## Що має вийти

Один розкривний список груп із пошуком усередині, без окремого ручного введення. Лаконічний екран встановлення, маленьке сіре «Продовжити у браузері» внизу та коротке підтвердження. Довідка Telegram згорнута в звичайному браузері й відкрита у розпізнаному вбудованому браузері. Навбар — унизу контейнера з одним safe-area відступом. Основний дизайн не змінювати.

## Перевірка

Запусти node --test tests/frontend.test.cjs (очікується 29 успішних тестів) та node --check для JS. Якщо локально доступні залежності Python, запусти також попередні серверні тести. Чесно відокрем результати нового запуску від історичних docs/*test-results*.

Запусти локальний вебсервер у тестовому середовищі, з окремим DATA_DIR або іншим способом ізоляції згідно з конфігурацією проєкту; не використовуй production-базу. Не запускай Telegram-бота з робочим токеном: це може конфліктувати з VPS. Не намагайся підключатися до VPS, SSH, продакшн-сервісів або перезапускати їх.

Дай мені URL і прості кроки для перевірки з телефона. Якщо потрібен доступ у локальній мережі, узгодь адресу/порт, не публікуй сервер в інтернет без дозволу. Для встановлення PWA на фізичному телефоні потрібен довірений HTTPS: локальна http LAN-адреса не є повноцінним тестом PWA.

Перевір ширини 320/360/375/390/430, малі висоти, landscape, Safari/PWA на iPhone 13 mini і Android, якщо маєш відповідні браузери/пристрої. Особливо: навбар на всіх вкладках, safe area, прокручування останньої картки, відкриття списку груп, клавіатура, порожній пошук, мережеві помилки, повернення з підтвердження браузерного режиму. Не вважай емуляцію Chromium доказом роботи на iOS.

Перевір Service Worker та ресурси ?v=2.6.1. Для першого запуску використай тестовий профіль/окремий origin. Не скидай робочу групу чи дані без мого дозволу.

## Git — лише після мого підтвердження

Зараз НЕ роби commit, push чи merge. Покажи diff, результати тестів і локальний сайт. Після мого явного дозволу зроби commit і push у погоджену окрему гілку, додавши тільки файли проєкту без секретів, робочих даних, самого ZIP і тимчасових папок. Перевір remote, не використовуй force push та не мерж у main без окремого дозволу. Якщо пряме відправлення заборонене правами — дай точну помилку, не обходь захист.

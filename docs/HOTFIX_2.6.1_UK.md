# MyKep 2.6.1 — спрощення старту та виправлення навігації

Це повний код на базі архіву 2.6.0 з інтерфейсними виправленнями. Серверний код і бот не змінювалися. Попередні серверні поліпшення збережено.

## Інтерфейс

Екран встановлення знову складається з іконки, заголовка, короткого пояснення та інструкції для поточного пристрою. У звичайному браузері довідку про Telegram згорнуто; у розпізнаному вбудованому браузері показано перехід у Safari/Chrome замість двох одночасних блоків. Telegram не завжди видає себе через User-Agent, тому згорнуту довідку можна відкрити вручну.

«Продовжити у браузері» — невеликий сірий текст унизу картки, з нормальною зоною натискання. Підтвердження збережено, але воно замінює основний текст, а не розтягує його додатковим блоком. Вибір запам’ятовується лише в поточній сесії вкладки.

На кроці групи — один розкривний список. Пошук з’являється всередині після розкриття й лише фільтрує готові групи. Самостійно вписану назву не можна зберегти. Відкриття списку не фокусує пошук автоматично, тож не викликає клавіатуру. Є повторне завантаження після помилки.

Навбар перенесено з position:fixed в останній рядок flex-контейнера висотою 100dvh (100vh як fallback). Прибрано дубльований нижній резерв 90px у контейнері. Під навбаром залишається max(10px, safe-area-inset-bottom), а не сума двох відступів. Основна область прокручується окремо. Кольори, картки, значки й помаранчеві акценти збережено.

Версії статичних ресурсів і кеш Service Worker оновлено до 2.6.1.

## Перевірено в the Computer

29 JavaScript-тестів пройшли: визначення платформ, PWA-підказки без beforeinstallprompt, підтвердження браузерного режиму, закрита додаткова довідка, вибір групи, фільтрація, помилки мережі/сховища, повторне завантаження, структура кешу. Використовується мінімальна модель DOM у Node, не справжній браузер.

node --check успішний для всіх static/js/*.js та static/sw.js. Перевірено HTML-структуру всіх трьох сторінок: навбар — останній дочірній елемент app-container, немає дубльованих ID. Усі Python-файли побайтово ідентичні 2.6.0; серверні тести й навантажувальні перевірки цього разу не запускалися.

## Обов’язково перевірити локально перед публікацією

Реальні Safari/PWA на iPhone 13 mini, Android і Telegram тут не запускалися. Тест CSS перевіряє структуру вихідного коду, а не реальне положення пікселів. Виправлення навігації потребує підтвердження на телефоні користувача.

Перевірити ширини 320, 360, 375, 390 та 430 CSS px; portrait/landscape; Safari з відкритою/згорнутою адресною панеллю; встановлений PWA; всі три вкладки. Навбар має бути біля нижнього краю без великого порожнього простору, вище системної смужки; останній блок налаштувань має бути доступний прокручуванням.

Пройти перший запуск у тестовому профілі: спочатку інсталяція, маленьке посилання, підтвердження, далі група. Розгорнути список, перевірити пошук із клавіатурою, вибір, порожній результат і повторне завантаження після відсутності мережі. Не очищати робочі дані користувача без згоди.

Для перевірки PWA на телефоні потрібен довірений HTTPS. Простий http://LAN-IP підходить для оцінки верстки, але не відтворює всі можливості встановлення/Service Worker. У DevTools перевірити завантаження ресурсів ?v=2.6.1, щоб не тестувати старий кеш.

Попередні docs/QA_UK.md і результати Python/навантаження стосуються базового релізу 2.6.0, не нового прогону.

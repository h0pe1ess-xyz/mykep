# MyKep 2.6.7: заголовки, зображення та мобільна PWA

База: останній завантажений `mykep-main2_6_6.zip_fil_07TStw0PeayZx0t.txt`, а не попереднє SEO-оновлення. Зміни зроблені цільово на його коді. Production та GitHub не змінювались.

## Заголовки та зображення

На головній короткий видимий MyKep став H2 зі збереженням класу й вигляду. Повний H1 «MyKep - розклад пар КЕП ІФНТУНГ» перенесений із noscript у звичайний DOM перед іншими заголовками. Він оформлений доступним sr-only, не display:none і не aria-hidden, тому не створює додаткового рядка на компактному dashboard. Без JS він видимий. На сторінці розкладу короткий MyKep також H2, є окремий повний H1. На about/settings їхні єдині H1 збережені.

Аватари отримали справжні квадратні розміри 460x460 та 184x184, loading=lazy, decoding=async, title. CSS лишає їх у попередніх круглих контейнерах. Іконки на about і в інструкції встановлення мають eager loading, розміри й title. Бінарні файли зображень не змінені. Title на img не є обов'язковою вимогою Google; доданий для зрозумілої підказки та аудиту.

## Мобільна доступність

Із трьох сторінок застосунку прибрані minimum-scale, maximum-scale та user-scalable=no. Доданий mobile-web-app-capable=yes. Apple-тег залишений для сумісності зі старими iOS: деякі аудитори можуть надалі показувати INFO про його застарілість. Це не критична помилка SEO, прибирати iOS-сумісність заради зеленого індикатора не потрібно.

CSS touch-action тепер manipulation: дозволяє pinch zoom. JS більше не скасовує мультидотик, WebKit gesture events чи panning збільшеного viewport. Однопальцевий контроль overscroll лишився; touchstart не блокується, щоб можна було додати другий палець. Висота модальних вікон не перераховується під час pinch zoom.

## iOS Home Screen

Раніше iOS мав 100lvh та абсолютну нижню навігацію. Це могло виносити її за видиму межу у відмінних viewport-контекстах. Тепер висота вимірюється через innerHeight/visualViewport при scale=1, оновлюється при resize/pageshow/rotation. Safe-area не віднімається в JS: його враховує CSS один раз.

iOS-shell має grid із minmax(0, 1fr) для вмісту й окремим рядком для навігації. Немає абсолютної nav, подвійного резервування нижнього відступу чи 100lvh. Ширина header/cards у портретному режимі збережена, повноширинний фон nav лишився. Є safe-area відступи в landscape. На дуже низьких екранах і з довгими назвами після спроб ущільнення dashboard переходить до внутрішнього scroll замість обрізання. Таймер не зменшується.

Це виправлення коду за знайденими проблемами, НЕ підтверджений результат на конкретному iPhone. Реальний Firefox iOS -> додати на домашній екран -> запуск іконкою потребує перевірки на пристрої. Safari-installed PWA, браузерні вкладки, Android і робота клавіатури теж входять до ручної перевірки.

## Що збережене

Короткі тире та актуальні описи користувача збережені. Згадки про сторонній однойменний сервіс не повертались. Усі Python-модулі, Android CSS/JS, логіка розкладу/налаштувань, JSON-довідник викладачів, manifest, llms-файли, robots, sitemap і всі зображення побайтово незмінні. У teacher-hints.js змінений лише параметр версії статичного URL, у pwa.js лише атрибути іконки. Немає міграцій, очищення localStorage або зміни ідентичності PWA.

Оновлені URL ресурсів і назва кешу до 2.6.7, версія в налаштуваннях/діагностиці, очікування версії у тестах. Старі docs/SEO_UPDATE_UK.md та BASELINE_PRESERVATION_UK.md описують історичне SEO-оновлення, не поточний реліз. Для застосування використовувати актуальний docs/ANTIGRAVITY_PROMPT_UK.txt та UPDATE_MANIFEST.json.

**MyKep** розроблений для перегляду розкладу занять коледжу з телефона або комп’ютера. Застосунок показує поточну пару, час до її завершення або початку наступної та розклад на тиждень. Підтримує встановлення на iOS та Android через PWA і перегляд раніше завантаженого розкладу без інтернету.

**Сайт:** [mykep.pp.ua](https://mykep.pp.ua)

## Можливості

На головній сторінці відображаються поточна пара, таймер до її завершення або початку наступної та заняття на день. Тижневий розклад доступний на окремій вкладці. Розклад, головна та налаштування перемикаються без перезавантаження сторінки, кнопками або горизонтальним свайпом. Вибір дня має власну горизонтальну прокрутку й не перемикає вкладки.

Після завершення пар або у вихідний головна показує найближчий навчальний день, час першої пари й завершення занять. Іконка поширення біля вибору тижня відкриває системне меню з картинкою вибраного дня, якщо браузер підтримує поширення файлів. Окремого прев’ю чи кнопки збереження немає. Картинка генерується на пристрої через Canvas без серверного рендерингу чи завантаження файлів на сервер. При ручному виборі тижня картинка вказує номер тижня замість календарної дати.

Академічна група обирається зі списку з пошуком. У налаштуваннях можна змінити групу, встановити тривалість пар для кожної зміни та повернути рекомендовані значення.

Інтерфейс має темну тему й адаптивну верстку для мобільних екранів. Для встановленого застосунку на iOS передбачені окремі стилі з урахуванням системних областей екрана.

## PWA та офлайн-режим

MyKep підтримує встановлення на головний екран iOS та Android і запуск в окремому вікні без панелі браузера. Встановлення через App Store або Google Play не потрібне.

| Платформа | Встановлення |
| :--- | :--- |
| iOS, Safari | «Поділитися» → «На початковий екран» |
| Android, Chrome | Меню браузера → «Встановити додаток» або «Додати на головний екран» |

Назви пунктів можуть відрізнятися залежно від версії браузера. Для вбудованих браузерів, зокрема Telegram, передбачена підказка про перехід у зовнішній браузер. Доступ без встановлення також збережено.

Service Worker кешує ресурси інтерфейсу, а розклад зберігається локально. Після успішного завантаження групи офлайн доступний увесь цикл 1–4 з урахуванням дат початку занять. Кеш зберігає до 12 наборів групи й тривалостей, захищаючи поточну основну групу. Перше завантаження та оновлення розкладу потребують інтернету.

## Архітектура

Python 3.11+, FastAPI й SQLite обслуговують API; інтерфейс використовує Vanilla JavaScript, HTML і CSS. Node.js потрібен лише для перевірок. Один Uvicorn worker працює за Nginx через loopback.

| Частина | Відповідальність |
| :--- | :--- |
| `main.py` | Життєвий цикл, публічний API, статичні файли та HTTP-заголовки |
| `schedule_service.py`, `teacher_hints.py`, `upstream.py` | Обмежене завантаження джерел, валідація, останні справні знімки |
| `database.py`, `analytics.py`, `activity_limits.py` | SQLite WAL, пакетний запис подій, обмеження черги та прийому |
| `admin_auth.py`, `admin_api.py`, `admin_stats.py` | Telegram-вхід, сесії, авторизація, адміністративні дії та агрегати |
| `server_metrics.py` | Обмежені за розміром метрики процесу й запитів |
| `static/js/` | Кеш даних, навігація, розклад, таймер, налаштування, PNG-поширення |
| `static/sw.js`, `scripts/release.py` | Узгоджений PWA shell із версіями та перевіркою SHA-256 |
| `admin_static/` | Окрема адміністративна сторінка й кеш лише її статичних ресурсів |

Розклад завантажується із сайту коледжу раз на 30 хвилин. Конкурентні оновлення серіалізовані; після помилки використовується останній справний знімок SQLite. Різке скорочення розкладу потребує повторного підтвердження джерелом. Адміністратор може повернути попередній перевірений знімок. На порожній базі API повертає 503 до першого успішного завантаження.

Події аналітики проходять через обмежену чергу й записуються пакетами. Детальна історія зберігається, добові підсумки оновлюються транзакційно. Технічні оновлення й поширення фото не зараховуються як перегляди. Окремий показник поширення PNG збирається з 2.10.3 після успішного завершення системного меню; він не підтверджує доставку отримувачу. Повторні події одного браузера й групи за 10 секунд об’єднуються, офлайн-події не надсилаються. В адмінці показуються агрегати, а не сирі ідентифікатори браузерів. Ліміти й кеші розраховані на один процес; збільшення кількості workers потребує окремої архітектурної зміни.

## Встановлення

```sh
git clone https://github.com/h0pe1ess-xyz/mykep.git
cd mykep
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
cp .env.example .env
.venv/bin/python main.py
```

У Windows використовуйте `python` та `.venv\Scripts\python.exe`; скопіюйте `.env.example` через `Copy-Item`. Локальна адреса за замовчуванням: `http://127.0.0.1:8000`. `.env`, база та резервні копії не входять до Git.

| Змінна | Призначення / значення за замовчуванням |
| :--- | :--- |
| `MYKEP_DB_PATH` | Шлях до SQLite; `schedule.db` у каталозі застосунку |
| `MYKEP_HOST`, `MYKEP_PORT` | Локальний запуск: `127.0.0.1`, `8000` |
| `SCHEDULE_REFRESH_SECONDS`, `SCHEDULE_RETRY_SECONDS` | Оновлення: 1800 с, повтор: 30 с |
| `TELEGRAM_BOT_TOKEN` | Серверний секрет перевірки Telegram Login |
| `ADMIN_TELEGRAM_IDS` | Необов'язкове звуження жорсткого allowlist у `config.py` |
| `ADMIN_PUBLIC_ORIGIN` | Точний origin адмінки; без значення порівнюється з Host |
| `ADMIN_COOKIE_SECURE` | `1`; `0` дозволений лише для локальної HTTP-перевірки |
| `ADMIN_SESSION_HOURS`, `ADMIN_IDLE_HOURS` | Абсолютний та неактивний термін сесії: 168 і 72 години |
| `ADMIN_COLLEGE_SIZE` | 1200, знаменник метрики охоплення |
| `PUBLIC_CSP` | `1`; залишайте увімкненим у розгортанні |

## Адміністрування

Адмінка доступна за `/admin/`. Для Telegram Login налаштуйте домен через `/setdomain` у BotFather та задайте `TELEGRAM_BOT_TOKEN` на сервері. Токен потрібний для перевірки підпису; застосунок не запускає Telegram polling, команди чи фонові звіти. Реальний вхід залежить також від налаштування домену в Telegram.

Сервер перевіряє HMAC-SHA256, вік даних до п'яти хвилин і дозволений Telegram ID. Повторне використання підписаних даних блокується SQLite. У базі зберігаються хеші випадкових токенів сесій; cookie має HttpOnly, Secure і SameSite=Strict. Зміни потребують CSRF-токена та перевірки походження. Кожен захищений маршрут перевіряє сесію. Парольного чи локального обходу входу немає.

Для входу у встановлену iOS PWA можна створити одноразовий код у вже авторизованій адмінці. Код діє три хвилини. Аварійний доступ із довіреної серверної консолі:

```sh
.venv/bin/python admin_cli.py code <allowed-telegram-id>
.venv/bin/python admin_cli.py revoke-all
```

Код є секретом: не зберігайте в журналах і не пересилайте стороннім. Журнал адміністративних дій зберігається 180 днів. API адмінки має `Cache-Control: no-store`; service worker не кешує відповіді API. Після невдалого мережевого виходу інтерфейс пропонує повторити його, бо серверна сесія могла залишитися активною.

## Розгортання й оновлення

Приклади в `deploy/` потрібно адаптувати до реальних шляхів, домену та користувача сервісу. HTTPS-сертифікати, DNS, firewall, резервування та моніторинг налаштовуються окремо. Nginx повинен приймати тільки відомий домен, передавати власні forwarding-заголовки та обмежувати тіло запиту. Uvicorn довіряє лише локальному проксі. Не виставляйте порт 8000 в інтернет.

Перед розгортанням:

1. Створіть перевірену резервну копію: `.venv/bin/python backup_database.py schedule.db backups/before-update.sqlite`
2. Якщо попередня інсталяція мала окремий `mykep-bot.service`, зупиніть і вимкніть його; приберіть `BOT_MODE` з оточення
3. Оновіть код і залежності, зберігши `.env`, SQLite та її WAL-файли; не копіюйте поверх них тестові дані
4. Перезапустіть лише вебсервіс та перевірте `/api/health`, адмінку, отримання розкладу й PWA-оновлення

SQLite backup API включає WAL; команда перевіряє цілісність копії та відновлення в тимчасовому каталозі. Це не замінює зовнішніх зашифрованих резервних копій і перевірки реального плану відновлення. Чинні міграції додають поля й таблиці без скидання історії. Історичні таблиці колишніх звітів залишаються недоторканими.

Після змін кешованих ресурсів збільшіть `VERSION` і виконайте `python scripts/release.py`. Генератор оновлює версії публічних та адміністративних ресурсів. `python scripts/release.py --check` перевіряє результат. Публічний worker відхиляє змішані чи неповні shell-ресурси; для HTML перевіряється маркер версії, оскільки Cloudflare може додавати службовий скрипт. Ключі налаштувань і схему локального кешу цей рефакторинг не скидає.

API зберігає публічні контракти. У `/api/admin/config` і `/api/admin/server` видалено лише поля прибраних режимів: `dev_login`, `dev_admin_ids`, `dev_login_enabled` та `bot`. `/api/admin/auth/dev` більше не існує.

## Перевірки

```sh
python -m pip install -r requirements.lock -r requirements-dev.txt
npm ci --ignore-scripts
python -m pip check
python -m ruff check .
python -m unittest discover -s tests -p 'test_*.py'
python scripts/benchmark_core.py
python scripts/release.py --check
python -m pip_audit -r requirements.lock --no-deps --disable-pip
npm audit
npm run check
npm run lint
npm test
npx playwright install --with-deps chromium webkit
npm run test:browser
```

Тести використовують синтетичні дані та тимчасові бази. Браузерні перевірки охоплюють навігацію, історію, налаштування, таймер, календар, PNG-поширення, відмови мережі, кеш і оновлення PWA. Адмінка перевіряється через локальний FastAPI з підписаними тестовими даними. Chromium/WebKit і мобільні viewport не замінюють фізичний iPhone, системне меню поширення та реальний Telegram-вхід.

GitHub Actions запускає `Backend` і `Frontend and PWA` для кожного push та pull request. Обидва jobs мають бути required status checks для `main` у налаштуваннях GitHub; сам YAML не блокує merge. Workflow не розгортає застосунок. `minimatch` зафіксований через npm override на виправленій версії, поки ESLint не оновить свою залежність.

Помилки й пропозиції: [Issues](https://github.com/h0pe1ess-xyz/mykep/issues). Для UI-проблем додайте кроки відтворення, модель пристрою, браузер і режим запуску: вкладка чи встановлена PWA.

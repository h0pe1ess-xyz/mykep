**MyKep** розроблений для перегляду розкладу занять коледжу з телефона або комп’ютера. Застосунок показує поточну пару, час до її завершення або початку наступної та розклад на тиждень. Підтримує встановлення на iOS та Android через PWA і перегляд раніше завантаженого розкладу без інтернету.

**Сайт:** [mykep.pp.ua](https://mykep.pp.ua)

## ⚙️ Можливості

На головній сторінці відображаються поточна пара, таймер до її завершення або початку наступної та заняття на день. Тижневий розклад доступний на окремій вкладці.

Академічна група обирається зі списку з пошуком. У налаштуваннях можна змінити групу, встановити тривалість пар для кожної зміни та повернути рекомендовані значення.

Інтерфейс має темну тему й адаптивну верстку для мобільних екранів. Для встановленого застосунку на iOS передбачені окремі стилі з урахуванням системних областей екрана.

## 📲 PWA та офлайн-режим

MyKep підтримує встановлення на головний екран iOS та Android і запуск в окремому вікні без панелі браузера. Встановлення через App Store або Google Play не потрібне.

| Платформа | Встановлення |
| :--- | :--- |
| iOS, Safari | «Поділитися» → «На початковий екран» |
| Android, Chrome | Меню браузера → «Встановити додаток» або «Додати на головний екран» |

Назви пунктів можуть відрізнятися залежно від версії браузера. Для вбудованих браузерів, зокрема Telegram, передбачена підказка про перехід у зовнішній браузер. Доступ без встановлення також збережено.

Service Worker кешує ресурси інтерфейсу, а розклад зберігається локально. Офлайн доступні вже завантажені дані. Перше завантаження та оновлення розкладу потребують інтернету.

### Розклад і кешування

Джерелом даних є [розклад на сайті коледжу](https://kep.nung.edu.ua/pages/education/schedule). Отримання, обробка та оновлення розкладу винесені в окремий серверний модуль. API використовує спільний кеш замість звернення до першоджерела на кожен запит користувача.

Остання успішно отримана копія зберігається в SQLite та завантажується після перезапуску сервера. Якщо джерело тимчасово недоступне, застосунок продовжує використовувати цю копію. На першому запуску, поки збережених даних немає, API повідомляє про тимчасову недоступність розкладу.

### Статистика та Telegram-бот

Події перегляду розкладу накопичуються в черзі й записуються в базу пакетами. Запити списку груп не враховуються як перегляди розкладу.

Telegram-бот надає адміністраторам статистику та щоденні звіти. Підтримуються запуск разом із вебсервером або окремим процесом. Для роботи сайту налаштування бота не обов’язкове.

## 🚀 Локальний запуск

Потрібен Python 3.11 або новіший. Для встановлення залежностей і першого отримання розкладу необхідне підключення до інтернету.

### Клонування репозиторію

````bash
git clone https://github.com/h0pe1ess-xyz/mykep.git
cd mykep
````

### Створення віртуального середовища

````bash
python -m venv .venv
````

Активація на Linux та macOS:

````bash
source .venv/bin/activate
````

Активація на Windows у PowerShell:

````powershell
.\.venv\Scripts\Activate.ps1
````

### Встановлення залежностей

````bash
python -m pip install -r requirements.txt
````

### Запуск сервера

````bash
python main.py
````

Альтернативний запуск через Uvicorn:

````bash
python -m uvicorn main:app --host 127.0.0.1 --port 8000 --workers 1
````

Локальна адреса: **[http://localhost:8000](http://localhost:8000)**.

База `schedule.db` створюється автоматично. Під час першого запуску розклад і список груп стають доступними після успішного отримання даних із першоджерела.

Для перевірки PWA на тому самому пристрої підходить `localhost`. Для встановлення з телефона через мережеву адресу потрібен HTTPS: звичайне HTTP-підключення до IP-адреси комп’ютера не забезпечує необхідного захищеного контексту.

## 🔧 Налаштування

Змінні середовища завантажуються з `.env` у корені проєкту або з оточення процесу.

| Змінна | Призначення | Типове значення |
| :--- | :--- | :--- |
| `MYKEP_DB_PATH` | Шлях до бази SQLite | `schedule.db` у корені проєкту |
| `SCHEDULE_REFRESH_SECONDS` | Інтервал оновлення розкладу в секундах | `1800` |
| `SCHEDULE_RETRY_SECONDS` | Інтервал повторної спроби після помилки | `30` |
| `BOT_MODE` | Режим запуску бота (`disabled` / `embedded` / `external`) | `disabled` |
| `TELEGRAM_BOT_TOKEN` | Токен Telegram-бота | Не задано |
| `ADMIN_TELEGRAM_IDS` | Звуження списку адмінів /admin (тільки в межах жорсткого allowlist) | `1125085502,1320649428` |
| `ADMIN_PUBLIC_ORIGIN` | Публічний origin для перевірки POST-запитів адмінки | Host запиту |
| `ADMIN_COOKIE_SECURE` | `0` — лише для локального http | `1` |
| `ADMIN_DEV_LOGIN` | `1` — вхід без Telegram з localhost (лише локально!) | `0` |
| `PUBLIC_CSP` | Content-Security-Policy для публічного сайту | `1` |

Адмін-панель: `/admin` — детально в [ADMIN.md](ADMIN.md).

### Підключення бота

Приклад `.env` для запуску бота разом із сайтом:

````dotenv
TELEGRAM_BOT_TOKEN=your_bot_token
TELEGRAM_ADMIN_IDS=123456789,987654321
BOT_MODE=embedded
````

Значення токена та ID наведені як приклад і замінюються даними конкретного розгортання. Без `TELEGRAM_BOT_TOKEN` вбудований бот не запускається.

Для окремого процесу використовується `BOT_MODE=external` у налаштуваннях вебсервера. Бот запускається окремою командою:

````bash
python bot.py
````

Одночасний запуск вбудованого й окремого бота з одним токеном не передбачений.

## 🌐 Розгортання

Каталог `deploy/` містить приклади systemd-сервісів для вебсервера й бота та конфігурації Nginx. Шляхи, користувач сервісу й параметри оточення налаштовуються під конкретний сервер. Для роботи PWA за публічною адресою потрібен HTTPS.

Приклад вебсервера розрахований на один Uvicorn worker та окремий процес бота. Збільшення кількості процесів потребує окремої перевірки фонових задач, кешування та роботи з базою. Допустиме навантаження залежить від ресурсів сервера й умов розгортання.

Перед оновленням потрібна резервна копія робочої бази. `.env`, `schedule.db` та службові файли SQLite не належать до вихідного коду й не повинні потрапляти в Git. Оновлення застосунку не повинне перезаписувати робочі дані.

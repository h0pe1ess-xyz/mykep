# MyKep 2.6.0 — зміни

## Інтерфейс без редизайну

Збережено темну палітру, помаранчеві акценти, таймер-дугу, картки, авторів та нижню навігацію. На першому запуску додано справжній нативний випадаючий список груп із пошуком. Дані надходять із того самого `/api/groups`, що використовується в налаштуваннях; при помилці є повтор і ручний ввід.

Попередження про рекомендовані налаштування тепер формально пояснює 80/60 хвилин, вплив на час і таймер та те, що офіційний розклад коледжу не змінюється. «Відміна» замінена на «Скасувати».

Адаптація: dynamic viewport, safe areas, visualViewport клавіатури, прокручування невисоких вікон, відмова від абсолютної висоти слайдів, заборона стискання карток, переноси довгих текстів, точкові правила для ширини до 375 px. Відновлено масштабування для доступності та прибрано глобальне блокування дотиків біля лівого краю. Зберігається максимальна ширина основного інтерфейсу 400 px.

## PWA і браузери

Окремий модуль `pwa.js`: інструкції Safari та Android, необов’язкова кнопка native install, підказка про зовнішній браузер для Telegram/WebView, копіювання посилання. Загальна Telegram-інструкція видима й коли застосунок приховує своє походження. «Продовжити у браузері» вимагає одного додаткового підтвердження; згода діє в поточній сесії вкладки. У налаштуваннях є доступ до інструкції.

Виправлено service worker: замість неіснуючого `/app.js` кешуються реальні модулі JS, CSS та потрібні ресурси. Додано 192/512 іконки й окрему maskable-іконку, scope/id manifest. API не кешується service worker-ом. Пошкоджений або чужий локальний кеш не спричиняє аварії; за відсутності даних показується помилка, а не вихідний день. Старий формат локального кешу безпечним чином ігнорується й оновлюється онлайн. Відкритий дашборд/розклад оновлюється при поверненні після паузи та періодично, щоб не залишатися на вчорашньому дні.

## Сервер і статистика

Винесено конфігурацію, роботу з SQLite та сервіс розкладу в окремі модулі. Один фоновий refresh-loop, single-flight lock і пауза після невдачі замість лавини запитів до коледжу. Останній добрий snapshot зберігається між перезапусками. Побудований розклад має обмежений кеш, групи зіставляються точно, параметри API перевіряються, час узгоджено з Києвом.

Записи аналітики — через обмежену чергу, пачками до 200 подій, із WAL та busy timeout. У звіти входять перегляди розкладу, а не відкриття списку груп. SQL-агрегація замінює завантаження всіх User-Agent у пам’ять. Додано health endpoint і облік втрачених подій.

Бот має ОС-захист від локального дублювання, кероване завершення polling/report-задач, повтор підключення з backoff, error handler та явну обробку конфліктів. Щоденні звіти використовують Київський час і збережені позначки доставки. Збережено старих адміністраторів, додано env-перевизначення. Токен не зашито. Є сумісний embedded-режим та окремий процес для production.

## Комплект постачання

Додано тести, сценарій синтетичного бенчмарку, HTTP-навантажувальний скрипт для свого staging, `.env.example`, приклади systemd/nginx та інструкції. Старі `.venv`, робоча SQLite, статистичні дампи, тимчасовий diff і кеші Python до ZIP не включені. Оригінальні медіаресурси й профілі авторів збережені.

Межі виконаних перевірок описані в `docs/QA_UK.md`. Продакшн-деплой, реальний Telegram та фізичні телефони не перевірялися.
